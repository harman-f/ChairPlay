# P7: per-area `zoomFactor` experiment — CaneTLOTW/M.I.B._Research#179

## Hypothesis and scope

Status: **LIVE_UNVERIFIED**. The field inside an individual Type111 `viewAreas[]` dictionary is speculative. The existing iOS 27.2 analysis identifies `zoomFactor` on the display dictionary, and `updateViewArea` uses UUID, index, animation and adjacency fields. The available `CARScreenInfo` excerpt passes area dictionaries on but does not establish whether iOS reads a per-area zoom; do not treat this as protocol support or a negative finding.

The pinned P6 build is PR `CaneTLOTW/M.I.B._Research#177` head `382750222986fd56694442910cfb0c553feca4a1`. The P7 branch and draft PR are based on that exact head. In the actual patched `/info` builder, `ClusterProfile.advertise(info)` replaces the ALT_UUID entry with `ClusterProfile.displayEntry()` when a profile is active. The generic `AirPlayInfoPlist.displayEntry`/`areaDict` path is separately modified and tested; Type110 remains unchanged. No zoom value is added to `updateViewArea`, no socket control is added, and no user profile schema is changed.

## Implementation and activation

`scripts/apply_p7_area_zoom_probe.py` is a pin- and anchor-checked isolated post-P6 source transformation. With default/unknown setting it adds no area field and leaves global zoom untouched. For an explicitly launched process, environment `CHAIRPLAY_P7_PROBE=A` enables Type111 indices 4→100, 5→85, 6→70 and keeps the global value. `CHAIRPLAY_P7_PROBE=B` sends the same area values and omits the global Type111 zoom. A Java system property `chairplay.p7.probe`, if present, takes precedence and is used by tests. The switch is process-local; no existing installed configuration has been changed. A and B require separate connections and must not be mixed in an existing session.

The separate `p7-test-profile.json` is **prepared only, not installed or selected**. Its Views 0/1/2 select indices 4/5/6 respectively but use identical geometry for those three areas, one Maps scene/options, no shapes and display zoom 100. It is intended to remove the confounding in the existing profile, whose URLs, rectangles and overlays differ. Whether iOS accepts identical areas or honors per-area zoom is unverified. Area duplicates may themselves alter iOS behavior; record that possibility.
